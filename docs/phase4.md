# Phase 4 — The Front Desk

## Endpoints

| Method | Path | Description |
|---|---|---|
| GET | /health | Health check |
| GET | /listings | Ranked, filterable, paginated |
| GET | /listings/{id} | Detail with breakdown + duplicate sources |
| PATCH | /listings/{id} | Status update (new→interested→applied→responded→interview→closed) |
| POST | /rescore | Recompute from YAML, zero network calls |
| GET | /stats | Summary statistics |
| GET | /docs | OpenAPI docs (auto-generated by FastAPI) |

## Filters (all composable)

- `listing_type` — job or gig
- `remote` — true/false
- `min_score` — minimum composite score
- `source` — source platform
- `posted_since` — ISO date
- `degree_not_required` — true
- `status` — listing status
- `company` — partial match
- `page` / `per_page` — pagination (max 200 per page)

## Static export

`python -m backend.export_public` writes public dataset to `data/public_export.json`.

**Verified:** zero occurrences of status, notes, canonical_id, dedupe_score, created_at in export output. Only public fields: id, listing_type, source, board_slug, company_display, title_display, location_display, department, url, posted_at, is_remote, remote_confidence, description_quality, score, score_breakdown.

Score breakdown detail (per-scorer internals with full regex match info) is stripped from the export — only dimension scores and the composite are included.

## Verification

All endpoints exercised against the real 937-listing database:
- Combined filters: remote=true + min_score=40 + source=greenhouse → 10 results
- PATCH: status updated and filtered by status
- Invalid status returns 422 with valid options listed
- Missing listing returns 404 with clear message
- POST /rescore: re-scored 937, 2 dealbreakers
- Static export: valid JSON, no private fields
